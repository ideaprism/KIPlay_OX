# 12:55

매주 월요일 점심시간 마지막 5분에 열리는 전사 실시간 OX 서바이벌.
KIPI Playground 플랫폼의 주간 정규전 미니게임 MVP.

제품 명세는 [PRD.md](PRD.md)를 참조.

## 실행

Node.js 18 이상만 있으면 된다. **설치할 의존성이 없다.**

```bash
node server.js
```

| 화면 | 주소 |
|---|---|
| 참여자 | http://localhost:12055/ |
| 전광판 | http://localhost:12055/board.html |
| 운영자 | http://localhost:12055/admin.html |

포트와 운영 키는 환경변수로 바꾼다. `PORT=8080 ADMIN_KEY=비밀 node server.js`

## 혼자 체험해보기

**사람도 시간도 필요 없다.** 참여자 화면에서 **「혼자 체험해보기」**를 누르면 된다.

역할(신입 / 일반 / 원장), 함께할 인원(20~450명), 대기실 길이를 고르고 시작하면
빈자리를 봇이 채운다. 봇은 난이도별 목표 정답률(쉬움 85% · 보통 60% · 어려움 40%)에 맞춰
답하므로 집계 바, 생존자 감소 곡선, 탈락 피드, 서든데스가 실제 회차와 같은 모양으로 움직인다.

체험 중에는 화면 상단에 안내 띠가 떠서 실전 회차와 헷갈리지 않는다.
결과 화면의 **「한 판 더」**로 바로 다시 돌릴 수 있다.

역할별로 이런 것을 확인할 수 있다.

| 역할 | 볼 수 있는 것 |
|---|---|
| 🌱 신입 | 부활권 3초 선택 창. 쓸지 말지 고민하는 그 순간 |
| 일반 직원 | 표준 진행 |
| 👑 원장 | 왕관 표시, 전광판의 "원장님 생존 중", VIP 격파 집계 |

봇 정답률이 목표와 맞는지는 `node scripts/curve.js`로 실측할 수 있다.

## 실전처럼 돌려보기

1. **운영자 화면**을 열어둔다. 기본 키는 `kipi`.
2. **참여자 화면**을 여러 탭(또는 여러 폰)에서 열고 사번으로 입장한다.
3. **전광판**을 큰 화면에 띄운다.
4. 운영자 화면에서 대기실 길이를 정하고 **게임 시작**을 누른다.

진행이 막히면 운영자 화면의 **다음 단계로**가 현재 단계를 즉시 끝낸다. 시연 중 복구 수단이다.

### 사번 체계

사번은 **5자리**다. 명부(`data/employees.json`)에 등록된 사번은 `joinYear` 값을 그대로 쓰고,
명부에 없는 사번은 `idFormat` 규칙으로 입사연도를 추정해 자동 등록한다.

```json
"idFormat": { "digits": 5, "yearPrefix": 2, "defaultYears": 5 }
```

기본값은 **앞 2자리를 두 자리 입사연도로 해석**한다. `26005`는 2026년 입사 5번이 되어
2년차 미만이므로 부활권 1개를 받는다. 이 덕분에 명부를 450명분 채우지 않아도
아무 5자리나 넣어 테스트할 수 있다.

> **사내 사번이 순번제라면** `yearPrefix`를 `0`으로 바꾸고 `roster`를 인사 데이터로 채우면 된다.
> 그 경우 미등록 사번은 `defaultYears` 연차로 처리되어 부활권 대상에서 빠진다.
> 이 파일만 고치면 되고 코드는 건드릴 필요가 없다.

### VIP 이벤트

명부에서 `vip: true`인 사번으로 입장하면 왕관이 붙고, 전광판에 "원장님 생존 중"이
실시간 표시된다. 그보다 오래 살아남은 사람이 추첨 대상으로 집계된다.
기본 명부에는 `95001`(원장), `03014`(운영실장)이 들어 있다.

## 검증

```bash
node scripts/e2e.js
```

실제 HTTP/SSE로 플레이어를 붙여 게임을 끝까지 돌린다. 정상 진행, 부활권,
전멸 구제 후 서든데스, 체험 모드, 입력 검증까지 40개 항목. **현재 전부 통과.**

```bash
node scripts/load.js 450
```

450명 동시 접속 리허설. 12시 54분 59초의 접속 스파이크를 재현한다.

### 실측 결과

같은 머신에서 측정했으므로 네트워크 지연은 포함되지 않는다. 서버 처리 능력의 상한을 보는 수치다.

| 항목 | 450명 | 900명 |
|---|---|---|
| 로그인 처리량 | 3,103 req/s | 1,508 req/s |
| SSE 연결 수립 | 450개 / 115ms | 900개 / 527ms |
| 문항 도달 지연 p50 | 13ms | 87ms |
| 문항 도달 지연 p95 | 31ms | 117ms |
| 답안 제출 실패 | 0 / 2,250건 | 0 / 4,500건 |
| 서버 메모리 (rss) | 106MB | 155MB |

정원 450명 기준으로 **2배까지 여유가 있다.** 병목은 서버가 아니라 실제 회선이 될 것이므로,
사내망 실환경에서 한 번 더 리허설이 필요하다.

```
  admin.html           운영자 콘솔

scripts/
  e2e.js               게임 흐름 검증
  load.js              부하 리허설
```

### 설계 판단

**WebSocket이 아니라 SSE + POST.** 이 게임은 실시간 액션이 아니라 방송형 동기 게임이다.
전원이 같은 문제를 동시에 받고, 7초 안에 한 글자를 보내고, 결과를 함께 받는다.
양방향 채널이 필요 없으므로 단방향 SSE로 방송하고 답안은 평범한 POST로 받는다.
구현이 단순해지는 만큼 시연 당일 실패 확률이 낮아진다.

**서버는 권위를 가지고, 클라이언트는 렌더링만 한다.** 탈락 판정은 전부 서버가 하고
클라이언트는 결과를 그린다. 화면 효과가 상태를 결정하는 일이 없다.

**답안은 재시도한다.** 네트워크 순간 장애로 답안이 유실되면 그 사람은 틀려서가 아니라
회선 때문에 탈락한다. 이 게임에서 가장 나쁜 버그이므로, 응답 창이 열려 있는 동안 재시도하고
도달 여부를 화면에 표시한다. 버튼이 눌린 것과 서버가 받은 것은 다르다.

**끊긴 참여자는 정리한다.** 그러지 않으면 폰을 닫은 사람이 영구히 참가자로 집계되어
참여율 지표가 오염된다. 단 진행 중에는 정리하지 않는다. 재접속하면 생존 상태를 이어받아야 한다.

**단일 인스턴스로 간다.** 인스턴스를 늘리면 세션 고정과 공유 상태가 필요해져 복잡도만 오른다.
450명 규모에서는 서버 한 대가 정답이다.

## 아직 만들지 않은 것

| 항목 | 상태 |
|---|---|
| **문제 자동 출제 파이프라인** | 별도 논의 후 착수. 현재는 `data/questions.json`에서 읽는다 |
| 사내 SSO 연동 | 현재는 사번 조회만. 상품이 걸린 운영에는 SSO가 필요하다 |
| 시즌 포인트 영속화 | 현재는 회차 내에서만 계산하고 저장하지 않는다 |
| 부서 랭킹 대시보드 | 데이터 축적 이후 |
| 지난 회차 아카이브 | 주 1회 편성의 공백 6일을 메우는 장치 |

파이프라인은 `data/questions.json`의 스키마만 맞추면 그대로 연결된다.
문항마다 `evidence`(근거 원문 문장)를 요구하도록 되어 있고, 이 값이 없는 문항은
파이프라인 단계에서 폐기하는 것이 할루시네이션 차단의 핵심이다.
